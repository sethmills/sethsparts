Flash the LED controller

The strips are driven by a small board — an Adafruit Feather RP2040 Scorpio — that plugs into your Raspberry Pi over USB. It needs firmware on it before the app can light anything up.

This app can't flash it for you, and it would be lying if it pretended otherwise: the board is plugged into the Pi, and the app runs somewhere else entirely. What it can do is tell you exactly what to run where the board is, and then check the result for you afterwards — which is the part that usually gets guessed at.

Skipping this is fine if you have no LED strips, or you flashed the board already. Nothing else in the app depends on it, and you can come back to this page from Setup at any time.

1. Put the board into flashing mode

The board has a BOOTSEL button. With the Pi switched on:

  1. Hold BOOTSEL down.
  2. Plug the board into the Pi's USB port — a data cable, not a charge-only one.
  3. Let go of BOOTSEL once it's plugged in.

It should now appear to the Pi as a USB drive called RPI-RP2. That drive is the board, in the mode where it accepts firmware.

Already running CircuitPython? Then you don't need any of this — the board shows up as CIRCUITPY instead, and the script notices that and just replaces the firmware files. That's the usual case when you're updating rather than setting up a board for the first time.

2. Run the script on the Pi

Over SSH, on the Pi the board is plugged into. This is the same script whether you're flashing a brand-new board or updating one that already works: 

scp led-controller/pi/flash-scorpio.py pi:~/led-controller/pi/
ssh pi
python3 ~/led-controller/pi/flash-scorpio.py

It's interactive on purpose — the parts it can't do for you are physical (holding a button, watching whether strips light up), and the parts it can do are the ones people get wrong from written instructions alone. It will:

  1. Work out whether this is a fresh board or an update, from what's mounted.
  2. Install CircuitPython itself — fresh boards only (it needs the .uf2 for this board: circuitpython.org/board/adafruit_feather_rp2040_scorpio; drop it in scorpio-firmware/ or pass --uf2).
  3. Install the libraries the firmware imports (adafruit_neopxl8 and its dependencies) — fresh boards only, offering both the official circup route and the bundle zip.
  4. Copy boot.py and code.py onto the board.
  5. Check it: the board's serial channels, the Pi's service config, and a live command to the board.

Only want to look, without changing anything? python3 ~/led-controller/pi/flash-scorpio.py --check.

The one that costs an evening: boot.py asks for a second serial channel, and that only takes effect after a true hardware reset — press the board's reset button, or run microcontroller.reset() from its REPL. A soft reset (Ctrl-D) does not re-enumerate USB, so the channel silently stays missing and every command times out. The script checks for the channel and says so if it's absent.

3. Check that it worked

This is the check the app can do, and it's a real one: it asks the Pi to run the board's demo, which the Pi can only do by reaching the board over USB. So a pass means the firmware is running, not that a box was ticked.

The strips will run the demo for a few seconds and then switch themselves off, so have a look at them while it runs. If nothing is set up yet, this says so rather than failing mysteriously.

When it doesn't work

  • No drive appears at all. Almost always the cable — charge-only USB cables power the board and carry no data. Then check lsusb and dmesg | tail on the Pi.
  • RPI-RP2 appears but the board stays dark afterwards. Wrong .uf2 — it has to be the Feather RP2040 Scorpio image, not another RP2040 board's.
  • Script says the data channel is missing. That's the hardware-reset trap above; the board needs its reset button, not Ctrl-D.
  • The check says the Pi couldn't reach the board. The service is reading the wrong serial device. In /etc/led-controller/env, SCORPIO_SERIAL_PORT should point at the -if02 path under /dev/serial/by-id/ — the board's second channel. A bare /dev/ttyACM0 is ambiguous when both channels are present, and -if00 is the REPL, which will not answer commands. Then: sudo systemctl restart led-controller.
  • Nothing here is set up yet. The Pi side of this is led-controller/ in the repository — its README covers the service install, and answers this section in more detail.
