If you'd like your own address, using Cloudflare Tunnel

This is the route this app was built around. It gives you a real domain with a valid certificate, and no open ports on your router — the tunnel makes outbound connections, so nothing on the internet can reach in directly.

  1. Put your domain on Cloudflare (free plan is fine) so Cloudflare manages its DNS.
  2. In the Cloudflare dashboard: Zero Trust → Networks → Tunnels → Create a tunnel. Choose the Docker connector and name it, e.g. parts.
  3. Copy the tunnel token it gives you.
  4. Under the tunnel's Public Hostname tab, add your domain, and point it at http://sethsparts:3200 — that's the app container's name and port inside Docker. (If you renamed the service in docker-compose.yml, use that name.)
  5. Put the token in your .env file as TUNNEL_TOKEN=…, next to the other secrets.
  6. Run docker compose --profile tunnel up -d — the tunnel is an optional profile in docker-compose.yml, so it only starts when you ask for it. Without the --profile tunnel part you get just the app, on localhost.
  7. Set DJANGO_ALLOWED_HOSTS in .env to your domain, e.g. parts.example.com. Django refuses requests claiming a host it doesn't recognise, and this is that setting.

Not using Cloudflare?

Any reverse proxy that terminates HTTPS and forwards to the app will do — nginx, Caddy, Traefik, a Tailscale funnel. Two things matter: forward the X-Forwarded-Proto header, which the app already expects, and set DJANGO_ALLOWED_HOSTS to your domain.

If you only ever use this at home, skip all of it. The community map won't work until your shop is reachable, and nothing else cares.
