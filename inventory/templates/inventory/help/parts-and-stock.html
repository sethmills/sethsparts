Part, stock row, quantity

A part is the name. A stock row is a count of that part in one location. One part, many rows.

Edit a quantity on the part's page and only that row changes — the screws in the loft box stay where they are.

“10 aprox” and other honest numbers

Importing a spreadsheet left some quantities unreadable — “10 aprox”, “~50”, “several bags”. Rather than throw those away, a stock row keeps the original text alongside an optional number.

So a row can be:

  • A number, if you know it. “12”.
  • A number with the original wording kept beside it, if you parsed one out.
  • Just text, if you genuinely don't know. It shows as “unknown” and asks nothing of you.

An approximate number you trust is more useful than an exact one you don't. Don't turn this into an audit.

Units

Most parts count in each — nine resistors, four screws. That's the default and it renders as a bare number, so nothing looks different.

Some things aren't countable: wire, tubing, heat-shrink, filament, solder, glue. For those, set the part's unit to metres, feet, grams and so on, and every quantity for that part reads as “5 m” instead of a bare “5”.

The app never converts between units. Converting would silently rewrite numbers you counted by hand — “5 metres” becoming “500 centimetres” is a decision for you, not for software. Change the unit and you're saying what the number means, not doing arithmetic on it.

A single stock row can override the part's unit, because one shelf might hold a part counted individually while another holds it by length.

Reorder thresholds

Set a minimum quantity on a part and the reorder page lists it once your total across all locations drops below that. Filter by category when you're placing an order.

This is the difference between discovering you're out mid-project and knowing a week earlier.

Projects and builds

A project has a bill of materials: the parts and how many of each it needs. Building it deducts those quantities from stock, oldest rows first, and records what it used.

The build page shows coverage — what you have against what you need — so a shortfall is visible before you start rather than halfway through.
